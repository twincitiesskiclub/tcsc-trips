## Flagged, out of scope

Things that surfaced during triage but need an element moved, a color/contrast fix, or structural restructuring rather than a spacing/padding change — not numbered findings, not input to the five fix passes.

- **shared** — `app/templates/admin/partials/header.html` is dead code: nothing in the template tree includes it, so its flash-message block never renders. Flagging in case it was meant to be wired in.
- **shared** — `app/static/admin.js`'s `showMessage()` (lines 115-127) creates `.flash-message` elements and looks for a `.admin-content` container; neither exists in any template/CSS, so that code path is dead/broken. Functional bug, not a spacing defect.
- **members** — Tag-assign modal (users-list, mobile, `tag-modal` state): every role checkbox except the first (focused) one is invisible. Looks like a rendering/functional bug in `.mr-tag-cb-item input[type=checkbox]` (`app/templates/admin/users.html:191`), not spacing.
- **members** — users-list desktop select-mode: the checkbox element itself doesn't render at all (see finding #7 for the spacing side-effect); the missing element is a functional bug.
- **members** — Roles editor sticky-bar overlap (findings #4-#6) may need the pane's reserved bottom space or sticky-engagement logic actually restructured, not just a spacing-token change; flagging so it isn't scoped as "just tighten padding."
- **payments** — Line-2 metadata separators (`·`, built in `pay_buildRow`, `app/static/admin_payments.js:405-413`, inside `.pw-row-line2` which has `flex-wrap: wrap`) can get orphaned alone at the start of a wrapped line on tablet/mobile. Needs the separators restructured (e.g. CSS `::before` content instead of standalone flex items), not a spacing-value change.
- **payments** — Row-level and section-level checkboxes (`.pw-row-check input`, `.pw-sec-selectall`) render with no visible border/fill when unchecked, in every viewport and both variants. Looks like a missing border-color declaration (color/contrast), not padding/margin.
- **catalog** — Checkbox border/contrast renders inconsistently (invisible outline) for "Single Price Point" on trip-edit desktop and "Required" on event-edit/event-new question-row. Color/contrast issue, not spacing.
- **catalog** — `event-registrations` roster table (mobile) doesn't adapt to narrow viewports; columns (Team name, Contact email, Contact phone, Emergency contact) are simply cut off with no scroll affordance. Needs responsive table restructuring.
- **catalog** — Systemic/architectural note: `event_form.html` builds its 2-column rows with one grid (`gap:12px`, `.aef-field{gap:5px}`), while `trip_form.html`/`season_form.html` build 2-column rows as separate `grid gap-5` wrappers whose children also carry `mb-5`. This pattern mismatch is the root cause behind findings #20-#23; a page-by-page fix will keep recreating this bug family unless the pattern itself is unified across the three form templates.
- **practices** — practices-detail Leads picker (findings #13-#15): the deeper fix — making the checkbox and label lay out side-by-side inside `.lead-option` — is arguably a layout correction rather than pure spacing. The minimal fix (sizing the checkbox) was judged in-scope and recorded as findings; noting the boundary here in case a fixer judges otherwise.
- **practices** — `practices-list--row-drawer-draft--desktop.png` and its `-part2` continuation are pixel-identical (same scroll position both times) — a capture-tool artifact, not a UI defect.
- **slack** — `scheduled_tasks.html`'s "Refresh"/"Clear" buttons use raw `bg-gray-200` classes instead of the `admin-btn`/`admin-btn-secondary` classes used on `channel_sync.html` — a color/component-choice inconsistency, not spacing (padding on "Clear" matches).
- **slack** — Newsletter job cards ("Newsletter Daily Update", "Newsletter Sunday Finalize") omit the channel-override `<select>` present on other job cards — a content/structural difference, not spacing.
- **slack** — Skipper drawer: JS sets `titleEl.style.flexDirection = 'column'` intending the status badge to stack below the title, but it renders inline next to the title — a layout/behavior mismatch, not spacing.
- **slack** — channel-sync mobile status-card grid (`grid-cols-2`) produces uneven-looking card heights when "Not scheduled" wraps to two lines — a content/type-scale interaction, not spacing/padding.

## Notes for the fix passes
